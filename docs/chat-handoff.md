# 流式正文交接修复与验证

## 已确认的问题与边界

基线为 test 的 `3c18662`（Harness 0.1.5-rc.2）。直接执行已安装聊天模块的回放测试复现两条路径：

- 流式文本之后收到只有工具调用的 `assistant/message`，`settleMessage` 替换 blocks，正文变为不可见。
- `llm/retry` 调用 `resetForRetry`，清空 blocks 并隐藏节点。

用户描述的具体会话事件尚未获得，因此不能断言真实现场是哪一条路径。工具回执 `Answer delivered. Stop here.` 不是正文，也不能证明正文已持久化。本修复不更改工具协议、模型请求或调度。

## 实现约束

- 权威 `blocks`、`finalNode` 保持独立，展示使用可选的 `presentation`。临时快照只保存可展示文本和图片附件引用，不保存推理或工具参数，不注入最终消息、复制/分支使用的历史或模型上下文。
- 以已有事件 seq 和重试边界区分尝试，拒绝重复/迟到的已处理事件；重试不拼接上一尝试。只在替换/重试边界保存快照，不为每个 token 复制历史正文。
- 每个 ChatSnapshotBuilder 持有自己的交接投影，先完成同一轮次新旧节点的 upsert，再发布订阅通知。新工具/推理不能替代旧正文。replace 基线重建清除旧投影状态。
- 最新可见正文接替旧正文后，紧凑模式将旧正文折叠为草稿，普通模式保持展开。主动展开草稿不因最终轮次折叠被撤销。原有正文节点 key 和已有首个可见 anchor 保持稳定。
- 取消、失败、不完整和缺失最终正文有明确提示；只有最新步骤的可见、非中断、无工具调用的权威正文或图片回答可以标为最终结果。
- 过程折叠必须额外确认最终答案已出现在可见节点存储。模型增量被保存为草稿不代表最终交付完成。
- 刷新仅依赖持久化事件，不保证恢复未保存的流式片段。一个步骤至多保留一份上一尝试草稿；可展开的草稿由会话内投影持有，切换/重建释放，不新增持久化缓存。

## 验证方法

```sh
npx vitest run test/chat-handoff.test.ts
node scripts/check-chat-handoff.cjs
npm run typecheck
npm run build
```

测试直接加载已安装模块，不靠源码字符串断言业务结果。原生 Electron 测试复用随包前端的 React、Markdown、store 及真实 ChatNodeSeat、AssistantNodeView、过程折叠组件；仅提供受控的事件源、槽位宿主和附件加载器，不启动真实会话、网络搜索或模型调用。

原生测试覆盖紧凑/普通模式、主动展开、三个缩放比例、逐帧正文非空、重试、工具交接、最终回答、图片及代码块。阅读历史时检查正文屏幕坐标，不错误要求 scrollY 固定；原有 ChatView 底部跟随算法不修改。完整生产会话录制和实机底部跟随仍应在取得现场事件后补验。

截图在 `artifacts/chat-handoff/`，跨平台工作流上传 PNG，不上传浏览器 profile。补丁使用 `node scripts/regenerate-chat-patch.mjs` 从仓库锁定的 tarball 与安装目录机械重建，随后运行 `npm ci` 验证可重装。

## 可选诊断

在目标聊天页面的开发者工具中设置 `globalThis.__DSH_CHAT_HANDOFF_DEBUG__ = true`，关闭时设为 false 或刷新页面。默认关闭，不自动上传。

仅在展示状态改变时记录固定字段：数字 turn/step/attempt/seq、事件类型、状态、文本块数和长度、工具块数、可见性和是否已被替代。不记录会话 ID、正文、推理、参数、附件、URL、请求头或凭据。诊断用于区分事件覆盖、重试及最终节点晚于结束边界等情况。
