# #69 供应商账号登录

## 使用

设置 → 模型 → 添加供应商，选择 `openai-codex` 或 `kimi-coding`，点击登录按钮。按流程提示打开官方页面、输入设备码，或在应用中回答流程要求的问题。登录成功后自动保存到现有供应商配置，并复用模型目录和默认模型选择机制。

取消按钮、关闭编辑卡或切换供应商会撤销当前尝试；登录失败可以重试。浏览器意外消失时，后台尝试会在失去轮询 15 分钟后清理，以给切到官方登录页的用户留出时间。授权协议自身也可能提前超时。

只使用 API Key 的供应商保持原有输入方式。已配置的显式 API Key 优先；没有有效 Key 时，有授权记录的供应商可走账号登录。认证信息仍由 Harness 凭据服务保存，浏览器只接收状态、提示和设备码，不接收访问/刷新令牌。

## 扩展

`LlmConfigurableProvider.authFlow` 引用已注册授权流程的凭据记录 key。UI 不识别特定供应商协议，统一显示 notify 与 text/secret/select prompt。

pi-ai 默认给 Codex、Kimi 声明 flow；其他路由可显式声明，例如：

```yaml
llm-pi-ai:
  providers:
    openai-codex:
      authFlow: llm-pi-ai/openai-codex
    kimi-coding:
      authFlow: llm-pi-ai/kimi-coding
```

pi-ai 的 `authFlow` 必须为该路由自身的 `llm-pi-ai/<provider>`，以保证可用性检查和模型调用读取同一个记录。账号凭据的兑换、刷新和撤销信号由既有 pi-ai/Harness 服务负责。

## 尚需人工验证

需本人在官方页面完成真实账号授权，再发送一次模型请求，验证账号套餐、模型权限和令牌刷新。未代替用户完成账号登录，未进行真实计费调用，也未据此关闭 Issue。
